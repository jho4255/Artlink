## 1. 새로 생긴 기능

### 임시저장 (갤러리 비공개)
작가가 작품 정보를 **다 채우지 않아도** 작성한 만큼 서버에 보관할 수 있습니다. 임시저장한 작품은 `draft: true`로 표시되어 **갤러리·관리자에게는 보이지 않습니다.**

- 숨기는 일은 **서버에서** 합니다 (`backend/src/routes/operation.ts`의 `publicSubmission` / `publishedArtworks`).
  프론트에서 감추면 목록·PDF·캡션·정산·독촉 대상 판단·대시보드 카운트 등 경로마다 빠뜨리기 쉬워 한곳에서 차단했습니다.
- 정식 **[저장]** 을 눌러야 `draft`가 풀리고 갤러리에 공개됩니다(전체 필수값 + 대표작 검증).
- 대표작 인덱스는 걸러낸 배열 기준으로 다시 매핑합니다 — 안 그러면 엉뚱한 작품이 대표작이 됩니다.
- 임시저장 작품에 붙은 **작가노트 상세설명도 함께 감춥니다**(작품은 숨겼는데 설명 본문으로 제목·내용이 새는 것 방지).

### 저장 상태 4색 (`frontend/src/lib/saveState.ts`)
| 색 | 상태 | 의미 |
|---|---|---|
| 회색 | 작성 전 | 작품 추가만 하고 아직 아무 입력 없음 (서버로 보내지 않음) |
| 빨강 | 저장 안 됨 | 입력했지만 서버에 없음 — 새로고침하면 사라짐 |
| 노랑 | 임시저장 · 갤러리 비공개 | 서버에 있지만 갤러리엔 안 보임 |
| 초록 | ✓ 저장됨 | 갤러리에 공개, PDF·정산에 포함 |

카드 머리에 **상태 · [저장] · [삭제]** 를 모아 배치했습니다.

### 작품 사진 여러 장 한 번에 올리기
사진이 비어 있는 기존 작품 칸부터 채우고, 남으면 새 작품으로 추가합니다. 파일명이 작품명 기본값으로 들어갑니다(비어 있을 때만).

### 저장 전 이탈 경고 (`frontend/src/hooks/useUnsavedChanges.ts`)
브라우저 닫기·새로고침 / 뒤로가기 / 앱 안 링크 클릭 세 경로 모두에서 확인창을 띄웁니다.
(react-router의 `useBlocker`는 데이터 라우터 전용이라 이 앱의 `<BrowserRouter>`에선 못 씁니다 — 브라우저 이벤트로 처리.)

## 2. 화면 개선

### 작가 제출 화면
- **갤러리 관리 탭과 디자인 통일** — 세그먼트 탭 + 탭별 입력 상태 점(초록/회색), 헤더에 설명 문구.
- **모든 입력 칸에 항상 보이는 라벨** — placeholder는 값을 채우면 사라져 무슨 칸인지 알 수 없었습니다.
- **숫자만 입력** — 가로/세로(소수점 1개 허용), 제작년도(4자리), 가격. 모바일 숫자 키패드도 지정.
- **작품 사진 크게**(64px → 128/160px), 비율 유지(`object-contain`), 사진 아래선을 제작년도 칸 아래와 정렬.
- **입력 칸 오른쪽 끝 정렬** + 단위(`cm`·`원`)를 삭제(−)와 같은 세로 열에 배치.
- **작품 단위 저장** — 그 작품만 검증하므로 다른 작품이 비어 있어도 막히지 않습니다.

### 작가노트 작품별 상세설명
- 자유 입력 → **출품작 드롭다운 선택**으로 변경(설명 대상은 출품한 작품이므로).
- 한 작품에 설명은 하나만 — 이미 쓴 작품은 선택 불가, 추가 시 안 쓴 작품 자동 선택.
- **저장된 작품만** 선택 가능(임시저장분은 갤러리에 안 보이므로). 대표작 선택도 동일.
- 좌측 큰 이미지 + 우측 선택·설명 레이아웃.

### 갤러리 열람 화면
- 작가별 행: 이름 고정폭 + `truncate`로 요약(출품·약력·노트) 시작점을 정렬, 모바일은 2줄 접기.
- 출품리스트: 썸네일 + 제목/메타 2줄 + 가격 우측 정렬(`formatArtworkPrice`: `500,000원`, `비매`는 원문 유지).
- 작가노트: 전체 노트 / 작품별 상세설명(썸네일 + 제목 + 본문)으로 구조화.

## 3. 고친 버그

### 치명
| # | 증상 | 원인 |
|---|---|---|
| 1 | **대표작이 저장할 때마다 사라짐** | 전송 목록은 복제본(`{...a}`)인데 대표작 재매핑이 참조 비교(`===`)라 항상 실패 → `null` 저장. 갤러리는 엽서 대표작을 영영 못 받음 |
| 2 | **정산에서 엉뚱한 작품이 '판매됨'** | 갤러리는 draft 제외 목록 기준으로 판매를 기록하는데 작가의 `/my-settlement`는 원본 목록으로 계산 → 위치 기반 `artworkIndex`가 어긋남. 작가가 잘못된 내역에 수락 서명하는 구조 |

**2번 후속 조치**: 정산 입력을 **전시 종료 후로 제한**했습니다(`PUT /settlement`). 종료 전에는 작가가 출품 목록을 고칠 수 있어 인덱스 프레임이 흔들립니다.

### 주요
- 저장 완료 시 목록을 통째로 교체 → 저장 중 다른 작품에 입력하던 내용 유실 + 빈 칸이 밀리며 대표작 어긋남 → **항목별 제자리 갱신**, 저장 기준선은 **서버 응답** 기준.
- 작가노트 저장이 빈 칸까지 전송 → 갤러리에 빈 작품 노출.
- 갤러리 대시보드 제출 카운트에 임시저장 포함 → 목록은 비었는데 "제출 완료"로 표시되던 모순.
- 배열이 아닌 `artworkList`가 저장되면 갤러리 조회 전체가 500 → 400으로 거부.
- 이탈 경고 뒤로가기에서 확인창 2번 + 두 페이지 이탈, 저장 후 히스토리 항목 잔류.
- 대표작만 바꾸고 나가면 경고 없이 유실(변경 감지에 대표작 포함).
- **작품 삭제 시 대표작이 옆 작품으로 옮겨감**(대표작보다 앞을 지우면 인덱스가 밀림) → 삭제 위치 기준으로 보정.

### PDF (인쇄 화면 + ZIP 양쪽)
> ZIP 다운로드는 인쇄 화면(`OperationPrintPage`)이 아니라 `lib/operationPdf.ts`가 따로 생성합니다. 처음엔 인쇄 화면만 고쳐 ZIP에 반영되지 않았습니다.

- **작가노트 PDF에 작품 사진 누락** — 렌더링 자체가 없었고, 이미지 프리로드 대상에서도 빠져 인쇄창이 먼저 떴습니다.
- **이미지 찌그러짐** — `width`/`height` 동시 지정 + `object-fit:cover`. html2canvas는 `object-fit`을 재현하지 못해 박스에 꽉 늘려 그립니다 → **고정 박스 + `max-*`** 조합으로 교체(크기 통일, 비율 유지).
- 출품리스트 표: `table-layout:fixed`로 열 고정, 전 셀 가운데 정렬, 크기의 `cm` 줄바꿈 방지, 가격 콤마+원.
- 중복 제목(헤더에 이미 있는 '작가노트'·작가명) 제거.

### 모바일 잘림
- 운영 페이지 정산 행 — 카드/현금·판매가 컨트롤(고정 ~190px)이 한 줄이라 375px 초과 → 둘째 줄로 접기.
- 운영 페이지 바깥 그리드에 `min-w-0` 누락 → truncate 텍스트의 최소 폭이 컬럼을 밀어 **페이지 전체가 가로로 밀림**.
- 마이페이지 내 공모 카드 — grid 셀에 `min-w-0`이 없어 긴 제목이 truncate를 무력화하고 잘림.
- 관리자 승인 관리 — `grid-cols-[88px_1fr]`의 `1fr`은 `minmax(auto,1fr)`이라 긴 URL이 탭 전체를 가로로 밀던 것.
- 작가측 PDF 버튼 3개(합 ~364px > 343px), CV 탭 툴바, 히어로·혜택 관리 수정 버튼 터치 타겟(26px → 44px).

## 5. 알아둘 점 · 남은 것

**의도된 동작**
- 이미 공개(저장)된 작품을 수정한 뒤 **임시저장**하면 그 작품이 갤러리에서 일시적으로 사라집니다. 다시 정식 저장하면 복귀합니다(토스트로 안내).
- 작가 본인이 자기 문서를 인쇄해도 임시저장 작품은 나오지 않습니다(공식 문서 기준).

**남은 개선 여지 (급하지 않음)**
- 출품작 제목이 **완전히 같은 작품이 둘 이상**이면, 작가노트 상세설명이 첫 번째 작품의 사진·정보를 가져옵니다. 근본 해결은 제목 대신 작품 고유 id로 잇는 것.
- 저장된 작품의 **제목을 고치면** 그 작품에 붙은 노트 상세설명이 잠시 "(출품리스트에 없음)"으로 표시됩니다(값은 유지, 재저장 시 복구).
- 작가노트 저장은 상세설명 중 **작품 미선택이 하나라도 있으면** 전체 노트 저장도 막습니다.
- 캡션 HWP·자료 제출 독촉 라우트는 임시저장 필터가 적용됐지만 **전용 테스트는 없습니다**(다른 경로로 간접 검증).
- 판매 기록은 여전히 **위치 기반 `artworkIndex`** 입니다. 종료 후로 입력을 제한해 위험을 줄였지만, 장기적으로는 작품 고유 id 저장이 안전합니다.
