### F1. ✅(2026-09-19 수정) [P2] 홈의 `<img src="">` React 경고 — 페이지 HTML 을 이미지로 한 번 더 받는다
- `frontend/src/components/home/OngoingShows.tsx:33`, `components/home/ClosingSoonExhibitions.tsx:39`
  ```tsx
  <Thumb src={s.posterImage || s.gallery?.mainImage || ''} …/>
  <Thumb src={ex.imageUrl || ex.gallery?.mainImage || ''} …/>
  ```
- 증상: 포스터도 갤러리 대표사진도 없는 전시/공모가 홈 레일에 뜨면 `<img src="">` 가 그려진다.
  React 가 `An empty string ("") was passed to the src attribute. This may cause the browser to download the whole page again over the network.` 경고를 찍고,
  브라우저는 빈 `src` 를 **현재 문서 주소로 해석**해 index.html 을 이미지로 한 번 더 내려받는다(그리고 실패해 깨진 이미지 아이콘).
  **이것이 "홈에 `src=""` 경고가 있다"의 정체다** — 프로젝트 전체에서 `Thumb` 에 `''` 를 넘기는 곳은 이 두 곳뿐이다(grep 전수 확인).
- 원인: `Thumb`(`components/shared/Thumb.tsx:83-94`)은 `SkeletonImage` 와 달리 **빈 src 가드가 없다**.
  `thumbUrl('')` 은 `if (!url) return url` 로 `''` 를 그대로 돌려주고 그게 `<img src>` 로 간다.
  `onError` 가 `setFallback(true)` 를 걸지만 원본도 `''` 라 그림은 끝내 안 나온다(무한루프는 `if (!fallback)` 가드가 막는다).
- 방향: `Thumb` 안에서 `if (!src?.trim())` 이면 회색 자리(또는 `ImageOff`)를 그리고 `<img>` 자체를 렌더하지 않는 게 근본. 임시로는 호출부에서 `{src ? <Thumb…/> : <ImageOff/>}`.
  (`OperationPage`·`OperationClassicPage` 는 이미 `a.image ? <Thumb/> : <ImageOff/>` 패턴을 쓴다 — 홈만 안 따랐다.)

### F2. ✅(2026-09-19 수정) [P2] 배너 띠 색이 CORS 한 번 어긋나면 **영원히** 기본 남색 — Promise 가 아예 resolve 되지 않는다

### 2차 — 모바일 지원 모달 (F19 검증)

**B-확인: F19 재현됨 — iOS 안전영역이 있으면 지원 모달의 [취소]·[지원하기]가 하단 탭바에 덮여 안 눌린다**
- 재현: 작가(`artist1`)로 375×667, `/exhibitions/7` → [지원하기] → 모달 안쪽을 끝까지 스크롤.
- 실측(Chromium, `env(safe-area-inset-bottom)`=0):
  | 화면높이 | 탭바 top | 모달 카드 bottom | 버튼 줄 y…bottom | 클릭 가능 |
  |---|---|---|---|---|
  | 667 | 610 | **617** (7px 가림) | 557…593 | O |
  | 740 | 683 | **685** (2px 가림) | 625…661 | O |
  | 812 | 755 | 751 | 691…727 | O |
- **안전영역 34px 을 흉내내면**(`nav[aria-label="하단 내비게이션"]{padding-bottom:34px}`, 실제 iPhone 홈 인디케이터 값)
  탭바 top 이 **576** 으로 올라오고 버튼 줄(557…593)이 그 아래로 들어간다 —
  `document.elementFromPoint(버튼중앙)` 이 **`NAV.fixed inset-x-0 bottom-0 z-50 lg:hidden`** 을 돌려준다.
  즉 [취소]·[지원하기] **둘 다 클릭 불가**(`clickable:false`). 모달은 이미 끝까지 스크롤된 상태라 더 내릴 수도 없다.
- 정리: 카드가 탭바에 물리는 것은 **안전영역이 0 인 브라우저에서도 이미 일어나고**(667·740), 버튼이 실제로 막히는 것은
  안전영역이 있는 기기(iPhone X 이후 전부)다. z-index 가 둘 다 `z-50` 이라 DOM 순서로 탭바가 이긴다는 F19 의 분석이 맞다.
- 기대: 모달을 `z-[100]` 이상(또는 포털)으로, 또는 `BottomTabBar` 를 모달이 열렸을 때 숨길 것.
