## P1 — 실제 손해가 나거나 대부분이 겪는 것

### 1. 화면을 옮겨도 스크롤 위치가 그대로 따라온다 (전 화면 공통)
- 재현(크롬 실측): 상세에서 [지원하기]까지 내려 누르면 **지원서가 scrollY 1151(PC) / 952(모바일)에서 열린다** — 제목·"홈페이지 내용으로 채웠어요" 안내·1번 약력 칸이 화면 위로 지나가 있고
  경력 중간~작품 사진부터 보인다. 모바일은 목록에서 카드를 누르면 상세가 포스터를 지난 자리(468)에서 열린다. 공모 등록 직후 [내 공모]도 목록 중간이라 방금 올린 공고가 안 보인다.
- 원인: `frontend/src/main.tsx:42` `<BrowserRouter>` — 경로가 바뀔 때 맨 위로 올리는 장치가 앱 어디에도 없다(`scrollTo(0` 검색 0건). 딥링크(`?ex=`)로 가는 화면만 제 카드로 스크롤해서 멀쩡하다.
- 방향: 경로(pathname)가 바뀔 때 맨 위로. 뒤로가기(POP)·`?tab=`·`?work=` 처럼 같은 화면 안의 변화는 건드리지 않는다.

### 2. 정산 입력이 저장 전에 경고 없이 사라진다
- 재현: [내 공모] 카드의 [운영] → 정산에서 판매 체크·판매가 입력('저장 안 된 변경' 칩이 뜬다) → 카드의 [지원자] 탭을 눌렀다 돌아오면 **입력이 전부 사라진다**. 상단 메뉴로 다른 화면에 가도 경고가 없다.
- 원인: `components/operation/SettlementSection.tsx` 에 `useUnsavedChanges` 가 없다(작가 출품 자료 편집기 `OperationPage.tsx:625` 에는 있다). 카드 탭을 바꾸면 운영 패널이 통째로 떼어진다.
- 작가 10명의 판매를 적다가 지원자 탭을 한 번 누르면 처음부터다. 정산 구역 자체를 접었다 펴는 것은 괜찮다(값이 남는다).

### 3. 전시 종료를 되돌리면 판매 기록이 다른 작품에 붙는다 (돈 기록)
- 재현(API, 단계 09 시드): 판매 `0:이른 아침(120만)` 이 있는 상태에서 `PATCH lifecycle {ended:false}` 200 → 갤러리 [대신 입력]으로 출품 순서 변경 200 → 다시 종료 → **`0:창밖의 오후(120만)`**. 작가 확인 기록은 그대로다(지문에 제목이 없다 — 규칙 26).
- 원인: `backend/src/routes/operation.ts:616` — 확정 취소는 판매가 있으면 막는데(바로 위), **종료 취소에는 그 검사가 없다**. 화면도 정산 요청 중·모두 확인 뒤에까지 [이전 단계로]를 보여 준다(`StatusPanel.tsx:166`).
- 방향: 판매 입력이나 정산 확인 요청이 있으면 종료 취소를 막는다(확정 취소와 같은 문구).

### 4. 갤러리를 삭제하면 정산 완료된 공모까지 통째로 지워진다
- 재현(데모 DB): 정산 완료 공모 직접 삭제 → 400 "정산이 완료된 공모는 삭제할 수 없습니다". 그 공모가 속한 **갤러리 삭제 → 200**, 공모·지원·출품 자료·판매·정산 확인 기록이 전부 사라지고 작가의 [내 전시]에서도 말없이 없어진다(알림 0건).
- 원인: `backend/src/routes/gallery.ts:476` 에 공모 쪽의 보호 규칙이 없다. 아트링크 주최 공모의 주관 갤러리여도 같다(그 공모는 운영 갤러리가 지울 수 없게 돼 있는데 갤러리 삭제로는 지워진다).
- 방향: 진행 중이거나 정산 기록이 있는 공모가 있으면 갤러리 삭제를 막고 이유를 말한다.

### 5. 작가 한 명의 이상한 출품 자료가 갤러리 운영 화면을 통째로 죽인다
- 재현(API): 수락 작가가 `PUT /operations/:id/me` 에 `note.sections` 를 글자로, 또는 작품 제목을 숫자로 보내면 200 으로 저장되고, 그 뒤 **갤러리의 `GET /submissions` 와 캡션(.hwp)이 500**. 그 공모의 출품 자료 구역이 아예 안 열린다.
- 원인: `operation.ts:289 submissionDataFrom` 은 `artworkList` 가 배열인지만 본다. `publicSubmission`(236)이 `.filter`·`.trim()` 을 그대로 부른다. 작품의 `image` 도 검증이 없다(`javascript:` 문자열이 그대로 저장된다 — 화면은 `<img>` 로만 써서 실행되지는 않는다).
- 정상 화면으로는 만들 수 없는 값이지만, 참여 작가 누구나 직접 호출로 할 수 있다. 방향: 저장할 때 모양·길이·주소를 검증(zod)하고, 읽는 쪽도 틀린 값을 건너뛰게.

14. **날짜 검증 구멍.** ①공모만 진행이면 화면 검사가 통째로 건너뛴다(`lib/utils.ts:242` `if (!deadline || !exhibitDate) return null`) — 시작일이 마감일보다 늦어도 통과, 서버도 201 →
    그 공고는 한 번도 목록에 못 뜬다. ②이미 지난 마감일로 등록 201. ③서버는 전시 종료일 < 시작일도 받는다(화면만 막는다).
15. **[내 전시]의 첫 탭이 그때그때 다르다.** 같은 계정이 PC 에선 [진행 중], 모바일에선 [받은 초대]로 열렸다. 초대 목록이 지원 목록보다 먼저 도착하면 '지원 0건'으로 보고 [받은 초대]로 굳는다(`MyPage.tsx:1176`).
16. **진행 중인 공모를 지울 수 있고 작가는 모른다.** 수락 작가·출품 자료·판매 입력이 있어도 정산 완료 전이면 삭제된다(`exhibition.ts:1529`). 확인창은 "지원 내역도 함께 삭제"뿐이고 작가에게 알림이 없다.
17. **로그인·프로필 요청 한도가 낮다.** `/api/auth/*` 전체가 IP 당 15분 30회(`index.ts:89`)인데 마이페이지·PDF 만들기·홈페이지 편집이 열 때마다 `/auth/me` 를 부르고 주소·닉네임 중복 확인도 여기다.
    같은 와이파이의 여러 명이나 한 사람의 반복 사용으로 넘으면 **15분간 로그인이 안 된다**. 방향: 엄한 한도는 로그인·가입에만.

## P3 — 작은 것
- 수락 알림 "운영 페이지에서 전시 정보를 입력"(옛 말 — 지금은 [내 전시]의 출품 자료), 거절 알림 "'거절'(으)로 변경"(화면은 '미선정').

## 보안 점검

### 막혀 있는 것(확인)
- 운영 라우트 35개 × 5역할 전부 401/403. 승인 전·반려 공모 상세는 남에게 404. 남의 지원 확인·상태 변경 404/403. 남의 갤러리 이름으로 공모 등록 403.
- 실서버: 개발자 로그인 404, CORS 는 `https://artlink.cc` 고정, 없는 API 는 JSON 404.
- JWT 시크릿은 없으면 부팅 실패, 역할은 요청마다 DB 에서 다시 읽는다. 로그인 실패 시간차 없음(더미 해시).
- 이미지 프록시는 우리 저장소 주소만(호스트 정확 일치, 리다이렉트 차단, 래스터 타입만).
- HTML 을 그대로 그리는 곳은 서식 글(`RichText`, 두 번 거름)과 PDF 미리보기뿐. 공지·이의·질문 답변은 글자로만 그린다(`<script>` 저장 → 글자로 표시).
- 정산: 옛 화면 수락 409, 금액 바뀐 작가만 재확인, 동시 수락 정원 초과 차단.
- raw SQL · `eval` · 외부 명령 실행 없음. 인증 없는 변경 라우트는 로그인·가입·방문 기록뿐.
