# ArtLook 화질 골든 회귀 (visual regression)

액자 렌더의 화질을 **눈이 아니라 수치로** 지키는 장치. "비슷해 보인다"는 판정 근거가
될 수 없어서 만들었다(2026-08-30).

## 왜 있나

ArtLook 결과물이 경쟁사(FrameIt)에 비해 "잘라 붙인 티가 난다"는 지적이 반복됐다.
원인을 추측으로 짚었다가 두 번 틀렸다(→ `artlook-scene-engine` 메모). 그래서 **레퍼런스를
고정해 두고 같은 코드로 재는** 방식으로 바꿨다.

## 쓰는 법

```bash
cd scratchpad/vt
node render.mjs                 # 스위트 10케이스 렌더 + 정확한 기하 기록
python run.py                   # 지표 + 임계 판정
python run.py --crops           # 100% 코너/변 크롭까지 (증거)
python run.py --save NAME       # 이번 결과를 기록으로 저장
python run.py --vs NAME         # 저장된 기록과 비교 (회귀 감시)
node sweep.mjs frames           # 액자 18종 × 매트 2단계 전수
node sweep.mjs scenes           # 장면 15개 전수
python golden.py                # FrameIt 레퍼런스를 같은 코드로 재측정
python mat.py                   # 매트·틈 지표 (2차 라운드)
python presence.py              # 존재감 지표 — 벽 소란도·주인공 크기·색 정합 (3차)
python artpreserve.py           # 작품 보존 — 자름/늘림/재채색/디테일 변형 감시 (3차)
python sweepcheck.py frames|scenes   # 전수 스윕을 모든 지표로 판정
node masks.mjs t01              # 디버그 마스크·그림자 레이어 + BEFORE/AFTER 추출
python masksheet.py t01         # 그 레이어로 시트 만들기 (상호배타·유출 검사 포함)
python audit4.py                # 그림자 감쇠 곡선·경계 날카로움을 골든과 대조
python wallcalm.py --write      # 장면별 벽 진정 세기 초기값(원본 결 기준)
python calmtune.py --write      # ★ 렌더를 보고 되먹임으로 최종 조정 (sweep scenes 먼저)
python lightdir.py --write      # 장면별 광원 방향을 **측정해서** scenes.json 에
python lightref.py              # FrameIt 조명 샘플(~/ArtLink/light/) 역분석 — 설계 근거
node light.mjs strengths        # 조명 강도 0/25/50/75/100 × 장면 4개
python lightcheck.py            # ★ 조명 판정 (작품 보존 · 방향성 · 마스크 테)
node light.mjs frames           # 조명 켠 채 액자 18종 × 매트 전수
SYN=0 SYNDIR=0 node render.mjs renders_off   # 합성 음영을 끈 기준 렌더
python syncheck.py              # ★ 7차 — 합성이 **지배적인가** (원본 대비 기여도)
python physics.py               # ★ 6차 — 그림자 방향 · 얇은 선 · 틈 바닥 (골든 대조)
node framelight.mjs             # ★ 6차 — 액자 18종이 **광원을 따르는가** (판만, 장면 없이)
node minsize.mjs                # 실치수 모드에서 작은 작품이 얼마나 작아지는가
```

로컬 dev 서버(`localhost:5173`)가 떠 있어야 한다. Python 은 numpy/pillow/scipy 필요.

## 구성

| 파일 | 하는 일 |
|---|---|
| `suite.json` | 10 케이스 정의(세로/가로/정사각 · 밝은/어두운 · 액자 5종+절차적+캔버스랩 · 매트 3단계 · 평벽/실내) |
| `render.mjs` | 각 케이스를 렌더하고 **페이지의 계측 훅**(`window.__artlook`)에서 조각·작품 사각형을 받아 적는다 |
| `metrics.py` | 단면 프로파일 기반 지표. 레퍼런스와 우리 렌더에 **같은 코드**를 쓴다 |
| `run.py` | 임계 판정 · 반복 간 비교 · 크롭 생성 |
| `golden.py` | FrameIt 레퍼런스 5장의 손확정 기하 + 같은 코드 측정 |
| `cases/` | FrameIt 레퍼런스 (저작권상 **커밋하지 않는다**) |
| `lightref.py` | FrameIt 조명 샘플 16장 역분석. 강도 4단계에서 '무엇이 변하는가'를 뽑는다 |
| `light.mjs` / `lightcheck.py` | 조명 슬라이더 회귀. 작품 dE·채도비·대비비·그늘구석·방향성·경계 spike |
| `reports/` | 반복별 기록(JSON). `--vs` 로 회귀를 잡는다 |

### 3차 라운드 — 존재감(`presence.py`)

"고급 제품 사진인가, 벽에 합성한 AI 이미지인가"를 잰다. 앞의 두 라운드가 **조각 안쪽**만
쟀다면 이건 **조각과 배경의 관계**다 — 같은 액자라도 벽이 시끄러우면 싸구려 목업이 된다.

| 지표 | 뜻 | 골든 실측 | 임계 |
|---|---|---|---|
| `piece_pct` | 조각이 화면에서 차지하는 **면적** % | 4.5~44.1 (Pro 44.1) | 26~58 |
| `wall_hf` | 벽의 고주파 결(1200px 정규화 std) | 2.9~12.6 (기준벽 2.9) | ≤4.5 |
| `hf_ratio` | 조각 디테일 ÷ 벽 디테일 | 1.0~5.3 | ≥1.3 |
| `con_ratio` | 조각 국부대비 ÷ 벽 국부대비 | 1.1~5.3 | ≥1.05 |
| `sat_rail` | 살의 채도 폭 — 크면 '플라스틱 나무' | 6~36 | ≤40 |
| `temp_dl` | 살 ↔ 벽 색상(ab) 거리 = 색온도 정합 | 6~35 | ≤40 |
| `rail_cv` | 네 살 폭의 변동계수 = 기하 왜곡 | 0~0.08 | ≤0.06 |

⚠️ **스위트는 작품 치수를 주지 않는다**(`selectedWork = null`). 2026-08-31 부터 실제
동작은 **실제 크기 단일 모드**라, 치수가 있는 작품은 벽 대비 실제 비율로 걸려 `piece_pct`
가 훨씬 낮아진다(흰 벽돌 기준 4호 5.7% · 30호 43.6%). 여기 지표는 **합성 품질**을 재는
것이지 실사용 크기를 재는 게 아니다 — 둘을 혼동하지 말 것.

⚠️ `wall_hf` 는 **밴드**다(2.5~4.5). 상한만 두면 벽을 뭉갤수록 점수가 좋아진다 —
그건 "액자만 선명하고 배경만 부드러운" 또 다른 합성 티다(골든 최저 2.86).

### 5차 라운드 — 살 길이방향 변화(`rail_pct`)

`audit5.py` 가 다섯 축을 골든과 대조한다: `edge_acut`(경계 날카로움) · `ao_lit`(빛 받는
쪽 폐색) · `rail_along`/`rail_pct`(살 길이방향 변화) · `gap_stages`/`gap_dark`(틈 구조·깊이) ·
`center_off`(중심 이탈). 이 중 **명확히 미달인 건 `rail_pct` 하나**였다(골든 8.5~104,
우리 3). 나머지는 전부 골든 범위 안이었고, `edge_acut` 의 이상치 2건은 **벽과 살 대비가
4밖에 안 되는** 측정 불가 케이스였다(가드를 20 으로 올려 해소).

`rail_pct` 는 `presence.py` 의 상시 지표로 들어갔다(≥8.0, 골든 최저 8.5).

### 4차 라운드 — 합성 해상도·그림자 꼬리·디버그 마스크

`node masks.mjs <case>` → `python masksheet.py <case>` 가 **엔진이 직접 뽑은** 여섯 마스크
(outer / front face / inner bevel·rabbet / mat / artwork opening / 접지·투영·반그림자)와
BEFORE·AFTER 를 한 장으로 만든다. 마스크를 하니스에서 다시 계산하지 않는 게 핵심 —
`?debug=1` 훅이 **본 렌더와 같은 quad·같은 워프**로 만들어 준다. 상호배타·판 밖 유출을
검사해 어긋나면 실패한다.

⚠️ **스윕(`sweep/`)은 JPEG 0.9 로 저장한다.** 얇고 얕은 골(슬림 액자 + 넓은 매트의
리베이트 21레벨)에서는 압축 잡음이 지표를 몇 % 흔든다 — 10케이스 스위트(`renders/`, PNG)
쪽이 판정 기준이다.

`artpreserve.py` 는 작품 자체를 원본 파일과 직접 대조한다(비율≤0.5% · ΔRGB≤14 ·
채도비 0.90~1.15 · 구조상관≥0.985). **ΔRGB 를 0 으로 만들려 하지 말 것** — 방 조명과
전혀 무관한 작품은 오려 붙인 것으로 보인다.

면제 규칙(임계 완화가 아니라 **해당 없음**):
- `rail_span` — 살 12px 미만은 프로파일을 담을 자리가 없다(레퍼런스도 8px 짜리는 6.8).
- `rebate_ratio` — 액자 없는 캔버스랩엔 리베이트가 물리적으로 없다(FrameIt 캔버스랩 0.133).

## ⚠️ 측정에서 겪은 함정 (다시 밟지 말 것)

1. **조각 사각형을 이미지에서 다시 찾지 말 것.** 색으로 찾으면 투영 그림자가 조각으로
   잡혀 경계가 16px 밀린다(case_00 실측). 우리 렌더는 계측 훅이 정확히 알려준다.
2. **두께가 있으면 실루엣 ≠ 앞면.** 캔버스랩은 뒷면이 더 나가므로 앞면만 재면 멀쩡한
   렌더가 검은 테를 가진 것처럼 나온다(실측 40.4 → 실제 결함 없음).
3. **비율 보존은 작품 사각형으로 잰다.** 실루엣으로 재면 옆면 때문에 어긋난다.
4. **리베이트를 작품 안에서 재지 말 것.** 어두운 그림이면 그림 자체가 최소값이라
   액자와 무관하게 큰 값이 나온다.
5. **절대값 지표는 재질·벽 밝기에 흔들린다.** 검은 액자는 옳게 그늘져도 절대 낙차가
   작고, 어두운 방에서는 `dir_tb` 가 줄어든다. 그래서 리베이트는 비율로 본다.
6. **우리 워터마크를 벽으로 세지 말 것.** 우하단 'ArtLink' 는 획 굵기가 딱 2~8px 대역이라
   대비 100 이 넘는 글자가 표본에 섞인다 — 흰 벽돌(원본 결 3.22)이 **5.29** 로 측정된
   원인이 이것이었다. 벽이 시끄러운 게 아니라 글자를 벽으로 세고 있었다.
7. **접지 그림자를 깊게 훑지 말 것.** 실내 장면은 작품 아래에 협탁·콘솔이 있어서 띠의
   끝이 가구다(t03 실측: 벽 158 → 159px 아래부터 34). 기준 밝기가 무너져 멀쩡한 그림자가
   **−104** 로 뒤집힌다. 지금은 ①물체를 만나면 띠를 끊고 ②'회복해 도달한 밝기'(띠의
   최댓값)를 기준으로 삼고 ③낙차는 **고정 위치가 아니라 가장 어두운 지점**에서 잰다
   (조각이 커지면 '폭의 1%'가 이미 절반쯤 회복된 자리가 된다 — stone 실측 15 → 7).

## 조명 지표 (2026-08-31) — `lightcheck.py`

레퍼런스는 FrameIt Pro 조명 샘플 16장(`~/ArtLink/light/`, **커밋 금지**).
프리셋 12 + **같은 프리셋의 강도 4단계**(20/50/70/100)가 있어 설계를 수치로 정할 수 있었다.

| 지표 | 뜻 | 강도 100 실측 | 임계 |
|---|---|---|---|
| `작품 dE` | 조명 0 대비 작품 픽셀의 평균 \|ΔRGB\| | 0.7~2.8 | ≤12 |
| `채도비` | 작품 채도 비 | 0.90~1.00 | 0.90~1.10 (artpreserve 와 **같은 값**) |
| `대비비` | 작품 지역 대비 비 | 0.98~1.00 | ≥0.90 |
| `그늘구석` | 광원 **반대쪽** 구석의 밝기 배율 | 0.67~0.70 | 0.62~0.84 |
| `방향성` | 광원 쪽 구석 배율 ÷ 그늘 쪽 배율 | 1.42~1.49 | ≥1.06 (1 이면 그냥 비네트다) |
| `경계 spike` | 조각 경계의 검은 테 (조명이 마스크 테를 만드는가) | 2.3~4.6, 무변화 | ≤12 |

⚠️ **FrameIt 과 같은 값을 목표로 삼지 말 것.** 그쪽은 강도 50 부터 작품이 무너진다
(작품 채도 92.6 → 63.7 → 46.5, 지역 대비 14.2 → 9.4). 우리 강도 100 은 그쪽 30~40 쯤이고,
그 대신 작품 보존 약속(채도비 0.90)을 **조명을 끝까지 올려도** 지킨다.

⚠️ **구석 배율을 네 구석 평균으로 재지 말 것** — 편심 필드라 광원 쪽 구석은 거의 안 어두워져
평균이 희석된다. 조명 세기는 **그늘 쪽 구석**으로 본다.

| `rail_line` | 살의 1~2px 임펄스(=그어 넣은 선) | 2.1~14.4 | 최대 **60.6** | 최대 30.7 |
| `Δ` (framelight) | 액자가 광원에 반응하는 폭 | — | 플로터 **0** | 전 18종 5.1~37 |
| 작품 밝기 편차 | 액자를 바꿀 때 작품이 변하나 | 0 이어야 | 1.6 | **0.5** |

### ⚠️ 지표를 만들다 두 번 틀렸다 (같은 실수를 반복하지 말 것)

1. **`gap_step`(한 표본 최대 낙차)은 버렸다.** 밝은 매트 옆 어두운 그림, 검은 살 옆 흰
   매트 같은 **정당한 재질 경계**를 stroke 와 구분하지 못한다. 실제로 브리핑이 시킨
   "작품 둘레 검은 stroke 제거"를 했더니 매트가 밝아져 이 값이 71→106 으로 **올랐다**
   — 고칠수록 나빠지는 지표였다. 구분하는 건 **중앙값 필터 잔차**다(단조 경계는 통과,
   1~2px 임펄스만 남는다).
2. **`dir_ok`(가장 어두운 변이 기대한 변인가)도 버렸다.** 좌상단 광이면 아래·오른쪽이
   **정확히 동점**이라 1% 차이로 성패가 갈려 멀쩡한 렌더가 4/9 로 나왔다. 네 변의 세기를
   **벡터로 합쳐 각도**를 본다(`dir_cos`).

⚠️ `aniso` 는 **벽 결이 바닥을 만든다** — 벽돌 줄눈이 있으면 그림자가 없어도 3~6% 가
나온다. 그래서 비(比)만 보지 말고 `dir_cos` 를 함께 볼 것. 우리 광원 쪽 변은 이미
2~6% 로 사실상 깨끗하고, 골든과의 차이는 대부분 **그늘 쪽 세기**(22 vs 27~50)다 —
브리핑이 "더 dramatic 하게 만들지 말라"고 했으므로 거기까지 올리지 않았다.

⚠️ `rail_line` 의 잔량은 **우리가 그린 선이 아니다.** 판(plate)만 재면 화이트 4~6 인데
장면 합성 후에는 22~25 다 — 워프·축소가 만드는 것이고, 골드(30.7)는 액자 **사진 자체의
반사 줄무늬**다(위치가 매번 달라진다. 우리가 그린 선은 늘 같은 자리에 나온다 — 그렇게
오크의 88% 스톱 꺾임을 찾았다). 재질 텍스처는 브리핑 7번이 보존하라고 한 것이다.

## 7차 라운드 (2026-09-01) — 덜어내기

기준이 바뀌었다: **'입체감이 더 강해졌나'가 아니라 '아무것도 안 한 것처럼 자연스러운가'.**
사용자가 든 실패 조건 — [액자 → 흰 테두리 → 검은 선 → 흰 매트 → 작품] 으로 층이 보이면 실패.

⚠️ **바닥값(`>=`) 임계를 골든 밴드로 바꿨다.** 바닥값은 "효과를 더 넣어라"로 민다 —
`rail_span` 은 바닥 20 을 통과하면서 골든(7~54)의 1.7배까지 부풀어 있었다.

⚠️⚠️ **절대값으로는 "합성이 지배적인가"를 못 가른다.** `rail_span` 이 밴드를 넘길래 음영을
더 깎으려 했는데, **합성을 완전히 끄고 재도 73.5**(켜면 75.2)였다 — 액자 **사진 자체**의
대비였다. 그래서 `syncheck.py` 는 **같은 입력으로 합성만 끈 렌더와 비교**한다.

| 지표 | 뜻 | 임계 | 현재 |
|---|---|---|---|
| `syn_delta` | 합성이 살 단면 대비를 몇 % 바꾸는가 | ≤25% | 0.9~20% |
| `dir_gain` | 장면 광원 추종이 **생기는가**(위살↔아래살 증가분) | ≥8 | +15~32 |

면제(임계 완화가 아니라 **해당 없음**): `syn_delta` 는 "원본 사진 보존"을 재는 것이라
**사진 액자에만** 뜻이 있다(절차적 액자는 보존할 원본이 없다). `dir_gain` 은 SYN 노브로
끄고 켜서 재는데 캔버스 랩의 옆면 음영은 그 노브를 타지 않는다(실제로는 광원을 따른다).

전/후 비교는 `?syn=`·`?syndir=` 쿼리로 같은 입력에서 뽑는다.
