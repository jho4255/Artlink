1. 위에 ArtLink 상단바·아래 ArtLink 하단 탭 — **남의 서비스 안의 프로필**로 읽힌다(인스타에서 들어온 방문자에게).
2. PC 머리말이 왼쪽에 이름만 있고 **오른쪽 절반이 빈다**. 대표작은 탭 아래에 와서 첫 화면에 작품이 없다(1280×720 기준).
3. 액션이 제각각: 작가 = 글자 링크 넷(이웃 추가·메시지·공유·QR) + 테두리 [수정] / 갤러리 = 회색 글자 링크 둘 + 조회수 배지 / 작품 창 = 반투명 알약 / 이웃 버튼만 따로 알약·파란 아이콘 변형이 있다.
4. 방문자가 할 수 있는 **다음 행동이 없다** — [메시지]는 로그인해야 하고, 작품을 보고 물어볼 길이 그것뿐이다.
5. 소식(ArtStory)을 올려도 내 홈페이지에는 하이라이트로 묶은 것만 보인다.
6. 갤러리는 "언제 열고 어디 있는지 · 지금 무슨 전시를 하는지"가 첫 화면에 없다.

## 2. 원칙 — 기존 작가와 [꾸미기]를 어떻게 엮는가

**한 줄 요약: 틀은 모두에게 자동으로 바뀌고, 내용·색·노출은 지금 값 그대로다. 새로 '보이게 되는 것'은 작가가 켠 것뿐이다.**

1. **틀(레이아웃)은 선택지가 아니다 — 전원에게 적용한다.**
   내 사이트 머리 · 표지 배치 · 버튼 줄 · 탭 순서 · 꼬리말 · 작품 페이지는 "같은 내용을 다르게 놓는 것"이다. 레이아웃을 고르게 하면 고르지 않은 47명이 옛 화면에 남는다(실측: 꾸미기를 만진 사람 0명).
2. **테마 규칙은 그대로**(규칙 49): `webTheme` 표식이 없으면 사이트 기본 톤. PDF 설정을 웹에 입히지 않는다. 새 부품은 전부 `var(--hp-…)` 만 쓴다 — 어두운 배경을 고른 작가의 화면에서 새 머리·꼬리말·문의 창·소식 카드가 깨지면 안 된다.
3. **이미 공개된 것을 다시 놓는 건 자동, 새 정보는 opt-in.**
   - 자동: 대표작을 표지로(지금도 [작품] 탭 맨 위에 공개돼 있다) · 올린 소식을 [소식] 탭으로(전체공개 소식은 이미 `/feed` 에 공개).
   - 작가가 켜야: 프로필 사진(지금 규칙 그대로) · 가격(그대로) · **비회원 문의 받기**(새 것 — 연락이 오는 통로가 생긴다).
   - 기본 켜짐 + 끌 수 있음: **전시 중 띠**(수락된 전시는 갤러리 페이지 '함께한 작가'에 이미 공개돼 있다). §9-4 에서 확인.
4. **새 꾸미기 값은 `designConfig` 의 웹 전용 키로.** 반드시 `lib/homepageTheme.ts WEB_ONLY_KEYS` 에 추가한다 — 빠뜨리면 PDF 화면에서 색 하나만 바꿔도 그 값이 사라진다(규칙 49 ②).
   `themeSavePatch` 규칙(안 건드렸으면 designConfig 를 아예 안 보낸다)도 그대로.
5. **미리보기는 같은 컴포넌트**(규칙 56). 새 표지·탭·버튼 줄은 `HomepageView` 안에 넣어 편집 화면 미리보기에 그대로 나오게 한다. 페이지 껍데기(사이트 머리·꼬리말)만 바깥.
6. **주인에게 한 번 알린다** — 배포 뒤 처음 자기 홈페이지에 온 주인에게 한 줄("홈페이지 모양이 새로워졌어요 · [꾸미기]", 닫으면 끝, `pdf-hint` 와 같은 방식). 방문자 화면에는 안내 문구를 두지 않는다(규칙 81 의 원칙).

## 3. 화면 설계

### 3-1. 내 사이트 모드 (껍데기)

대상 주소: `/@:handle` · `/portfolio/:id` · `/galleries/:id` (판정은 **새 파일 `lib/siteMode.ts isHomepagePath(pathname)` 한 곳** — `guestIntro.introAllowedAt` 의 홈페이지 판정도 이걸 쓰게 바꾼다. `/galleries/new` 는 제외).

이 주소에서 `Layout` 은:

| 부품 | 내 사이트 모드 |
|---|---|
| `Navbar` | **`SiteHeader`** 로 바꾼다 |
| `BottomTabBar` · `MyPageSideMenu` | 그리지 않는다(본문의 `pb-…`·사이드바 자리도 같이 뺀다) |
| 회사 정보 푸터 | **`SiteFooter`**(연락 · `Made with ArtLink`)로 바꾼다 |
| `GuestIntro` · `HomepageNudge` · `PushBanner` | 그대로(소개 팝업은 원래 이 주소에서 안 뜬다 — 규칙 73) |

`SiteHeader` (`components/homepage/SiteHeader.tsx`, 테마 변수 사용):
- 왼쪽: **주인 이름**(작가 이름 / 갤러리 이름) — 누르면 그 홈페이지의 첫 탭.
- **PC(lg↑): 가운데~오른쪽에 탭이 온다 — 머리의 메뉴가 곧 탭이다.** 별도 탭 막대를 그리지 않는다(막대가 두 줄이 되지 않게). 주소·규칙은 지금 그대로(`?tab=`, replace, 첫 탭은 쿼리 없음).
- 휴대폰: 머리(56px, sticky) = 이름 + [공유] 아이콘. 탭 막대는 지금처럼 표지 아래에 있고 머리 바로 밑에 붙는다(sticky).
- 맨 오른쪽: **작은 ArtLink 로고**(홈으로) — 로그인한 회원이면 그 옆에 벨·내 메뉴는 두지 않는다(§9-1 에서 확인. 대안은 '회원에겐 지금 상단바 유지').
- 주인에게만: [수정](지금 `ownerAction` — 머리 오른쪽으로 옮긴다. 규칙 60 의 "보던 탭의 묶음을 연다" 유지).
- ⚠️ sticky 높이를 상수 하나로: `lib/siteMode.ts SITE_HEADER_H = { base: 56, lg: 72 }`. `HomepageView` 의 `stickyTopPx`·`top-16 lg:top-20`, `PageTabBar` 의 붙는 위치, `scrollToTarget` 여백이 전부 이 값을 본다. 지금은 Navbar 높이(64/80)가 세 군데에 숫자로 박혀 있다.
- ⚠️ 탭 정의를 머리로 올리려면 탭 상태가 `Layout` 까지 올라와야 한다 → **컨텍스트 하나**(`SiteChromeContext`: `{ title, tabs, active, onSelect, ownerAction, share }`)를 두고 페이지가 채운다. 페이지가 아직 로딩이면 머리는 이름 자리만 비워 둔 채 같은 높이로 그린다(높이가 튀지 않게). 훅은 early return 위에(규칙 테스트 `hooksBeforeReturn`).

`SiteFooter`: 인스타(있으면) · [문의하기](받는 경우) · 오른쪽 끝 `Made with ArtLink`(artlink.cc 홈으로, 로고 색 규칙). 작가의 이메일·전화는 지금 공개 정보가 아니므로 싣지 않는다. 갤러리는 주소·전화·이메일·인스타(지금 공개 중인 것).

### 3-2. 작가 홈페이지 — 첫 화면(표지)

`HomepageView` 의 `<header>` 를 **표지**로 바꾼다. 대표작 = `pickHeroImage`(지정한 것, 없으면 첫 작품) — 지금 [작품] 탭 맨 위의 `Hero` 를 여기로 올린다(탭 안에서는 뺀다 — 같은 그림이 두 번 나오지 않게).

- **PC(md↑)**: 두 칸. 왼쪽 = (프로필 사진) · 이름(지금 크기) · 한 줄 소개(있으면) · 버튼 줄 · 전시 중 띠(있으면). 오른쪽 = 대표작(contain, 최대 높이 `min(60vh, 520px)`) + 그 아래 한 줄 캡션(`museumCaption`, 없으면 없음).
  칸 비율은 대표작 비율로: 가로 그림(≥1.2) 5:7 · 정사각 근처 6:6 · 세로 그림(≤0.8) 7:5. 대표작 뒤에 판(배경색 상자)을 **깔지 않는다**(규칙 45b 의 softPanel 교훈 — 비율이 다른 만큼 판만 보인다). 목업의 연한 배경판은 구현에서 뺀다.
- **휴대폰**: 대표작이 위(좌우 여백 안, 최대 높이 46vh) → 이름 → 한 줄 소개 → 버튼 줄 → 전시 중 띠 → 탭.
- 작품 0점: 지금의 '준비 중' 화면 그대로(규칙 60).
- 대표작을 누르면 그 작품 페이지(§3-5).
- ⚠️ 작품은 자르지 않는다(규칙 18). ⚠️ 원본을 받는다(t800 은 이 크기에서 뭉개진다 — 규칙 21). `loading="eager"`.
- 검증 기준(하니스): 1280×720·1440×900·1920×1080 에서 **첫 화면에 대표작 전체 + 이름 + 주 버튼이 보인다** / 390×844 에서 대표작·이름이 첫 화면에, 탭 막대가 1.3 화면 안에.

### 3-3. 버튼 — 한 벌로 (사용자 지적: 튄다 · 일관성 없다)

**규칙(작가·갤러리·작품 페이지 공통, 새 컴포넌트 `components/homepage/ActionRow.tsx`):**

| 급 | 모양 | 쓰는 곳 |
|---|---|---|
| **주 버튼 — 화면에 하나** | 채움 `background: var(--hp-ink); color: var(--hp-bg)` · 높이 44 · 좌우 20 · **모서리 각짐(반경 0)** · 14px medium · 아이콘 없음 | [문의하기] / 작품 페이지의 [작품 문의하기] |
| **보조 — 글자 링크** | 아이콘 14 + 글자 14 · 색 `var(--hp-sub)` → hover `var(--hp-ink)` + 밑줄 · 높이 44(누르는 영역) · 테두리·배경 없음 | [이웃 추가](`FollowButton variant="text"`) · [공유] · [QR] |
| **주인 도구** | 테두리 1px `var(--hp-ink)` · 높이 40 · 각짐 | [수정] 하나 |

- 지금 홈페이지 본문이 이미 쓰는 말투(각진 테두리 · 글자 링크)에 맞춘 것이다. **목업의 둥근 모서리 상자 3개(문의하기·이웃 추가·공유)는 버린다** — 그게 튀어 보인 원인: 사이트 어디에도 없는 6px 둥근 상자가 셋 나란히, 게다가 머리의 [문의]와 표지의 [문의하기]가 한 화면에 둘이었다.
- **[문의하기]는 한 화면에 하나.** 머리에는 두지 않는다. 표지에 하나, 꼬리말에 글자 링크로 하나(스크롤 끝).
- 순서 고정: `[문의하기]  이웃 추가 · 공유 · QR`. 인스타 링크는 버튼 줄에서 빼고 이름 아래 작은 줄(지역·분야 자리)과 꼬리말로.
- [메시지] 버튼은 [문의하기]로 합친다(§3-6). 한 화면에 '메시지'와 '문의'가 둘 다 있으면 무엇을 눌러야 할지 모른다.
- 갤러리의 조회수 배지(`ViewCountBadge`)는 버튼 줄에서 빼 이름 아래 작은 줄로(주인·관리자만 보는 값).
- `FollowButton` 의 알약(`pill`)·파란 아이콘(`iconOnly`) 변형은 다른 화면(작품 모달·커뮤니티)이 쓰므로 건드리지 않는다. 홈페이지 주소에서는 `text` 만.
- 색은 테마 변수만 — 회색 클래스(`text-gray-500`)·`rounded-full`·`bg-white/15` 금지. **소스 가드 테스트**로 막는다(`homepageChrome.test.ts`: `components/homepage/**` 와 `HomepageView.tsx` 에 `text-gray-`·`rounded-full`·16진수 색이 없다).
- 작품 창(`ArtworkViewer`)의 좋아요·공유는 어두운 바탕 위라 별개 규칙(지금 그대로). 작품 **페이지**(§3-5)는 위 규칙을 따른다.

### 3-4. [소식] 탭 (작가·갤러리 공통)

- 탭 id `news`, 이름 **소식**. 작가: `works · news · note · cv · file · guestbook` / 갤러리: §4-3.
- 내용(`components/homepage/NewsTab.tsx` — 두 페이지가 같이 쓴다):

- 주소 `?tab=news`. 소식 하나의 공유 주소는 지금처럼 `/feed?story=<id>`(바꾸지 않는다).

### 3-5. 작품 한 점의 페이지

지금: `?work=<id>` → 검은 `ArtworkViewer` 창. 바꾼 뒤: **같은 주소**가 홈페이지 안의 **작품 페이지**를 연다(새 라우트를 만들지 않는다 — 공유 링크·SEO·비회원 통계가 이미 `?work=` 를 쓴다).

- ⚠️ 목업의 '부분' 사진(작품 한 점에 사진 여러 장)은 새 데이터라 **이번 범위가 아니다**(§8).

## 4. 갤러리 홈페이지 (PC 포함)

### 4-1. 틀

작가와 **같은 껍데기**(`SiteHeader`·`SiteFooter`·`ActionRow`·탭이 머리에)·같은 테마 변수를 쓴다. 갤러리는 꾸미기(색·글꼴)가 없으므로 기본 톤으로 `themeCssVars(resolveHomepageTheme(null))` 를 얹는다 — gray 클래스를 변수로 바꾸는 작업이 대부분이다. **갤러리 꾸미기는 이번 범위가 아니다**(§8).

`GalleryDetailPage.tsx`(1,621줄)는 이번에 **머리 부분(표지·연락처·버튼 줄)만** `components/gallery/GalleryCover.tsx` 로 떼어 낸다. 탭 패널(소개·모집·작가·기록·리뷰)의 안쪽은 건드리지 않는다.

### 4-2. 첫 화면(표지)

- **PC(md↑)**: 두 칸. 왼쪽 = 지역(작은 글자) · 갤러리 이름 · 한 줄 소개(`description`) · 버튼 줄(`[문의하기]  이웃 추가 · 찜 · 공유`) · **방문 정보**(아래). 오른쪽 = 사진(지금의 `GalleryImageCarousel`, 7/12 폭, 비율 4:3 틀 안 contain — 전시장 사진이지만 포스터를 올린 갤러리가 있어 자르지 않는다).
  사진이 1장이면 화살표·점 없이 한 장. 사진이 없으면 한 칸(이름 덩어리만, 지금처럼).
  찜 하트는 사진 위에서 버튼 줄로 옮긴다(글자 링크 급 — `canFavorite(user)` 그대로, 규칙 7).
- **휴대폰**: 사진(전폭) → 이름 → 한 줄 소개 → 버튼 줄 → 방문 정보 → 지금 전시 → 탭.
- **방문 정보**(정의 목록, 있는 것만): 시간 · 주소 [지도] · 전화 [전화] · 이메일 · 인스타.
  - **시간 = 새 칸 `Gallery.openHours String?`**(자유 글, 80자 — "화–일 11:00–18:00 · 월 휴관"). 연락처 편집 안에 칸을 더한다(`PUT` 연락처 라우트 + zod). ⚠️ seed.ts upsert 의 update 블록에도(Critical Constraints 4).
  - 목업의 '지금 열려 있어요'는 **하지 않는다** — 자유 글로는 판정할 수 없고, 틀린 표시는 없는 것보다 나쁘다.
  - [지도] = `https://map.kakao.com/link/search/<주소>` 새 창(`rel="noopener"`). [전화] = `tel:`(휴대폰에서만 버튼, PC 는 번호 글자).
- **지금 전시**: 이 갤러리의 승인된 전시(`Show`) 가운데 진행 중(`getShowStatus==='ongoing'`, KST) 1건 → 포스터(자르지 않음) · `전시 중` · 제목 · 기간 → `/shows/:id`. 없으면 예정 1건(`전시 예정`). 없으면 안 그린다.
  서버: `GET /galleries/:id` 에 `currentShow`/`upcomingShow`(id·title·posterImage·startDate·endDate)를 싣는다(승인된 것만 — 규칙 23·24).
  PC 에서는 왼쪽 칸 맨 아래 카드, 또는 표지 아래 전폭 한 줄(사진이 없을 때).
- 주인 도구(사진 관리 패널 · 연락처 [수정])는 지금 자리·동작 그대로 두되 모양만 '주인 도구' 급으로.

### 4-3. 탭

지금 `소개 · 모집 중 · 함께한 작가 · 지난 전시 · 리뷰` → **`소개 · 모집 중 · 작가 · 지난 전시 · 소식 · 리뷰`**

- `news` 추가(§3-4, 대상 사용자 = `gallery.ownerId`). 주인에겐 비어 있어도 보인다.
- 이름표 '함께한 작가' → '작가'(머리 메뉴에 여섯 개가 한 줄에 들어가게). id(`artists`)·주소는 그대로.
- 순서·첫 탭은 지금 규칙 그대로(첫 탭이 바뀌면 `?tab=` 없는 옛 링크의 뜻이 바뀐다).
- PC 에서는 머리의 메뉴가 탭(§3-1). 6개가 1024px 에서 한 줄에 드는지 하니스로 잰다(안 들면 머리 아래 한 줄로 내린다 — 작가도 같은 폴백).

### 4-4. 빈 갤러리에서의 모습 (실제 4곳 중 3곳이 사진 1장 · 기록 0)

사진 1장 + 이름 + 한 줄 소개 + 주소·전화 + [소개] + [리뷰]만 있어도 첫 화면이 채워지는지가 합격 기준이다. 방문 정보가 왼쪽 칸을 채우므로 PC 에서 빈 절반이 생기지 않는다.

## 6. 구현할 때 걸리는 곳 (미리 적어 둔다)

1. **E2E 가 Navbar·하단 탭에 기대는 곳** — 작가·갤러리 페이지에서 상단 메뉴를 누르는 스펙이 깨진다. 먼저 `grep -rn "portfolio/\|/@\|galleries/" e2e/tests | grep -i "nav\|메뉴\|tab"` 로 목록을 만들 것. 최소 `10`·`30`·`32`·`37`·`53`·`54`·`56`·`57`·`74` 확인.
2. **sticky** — 탭 막대·`PageTabBar`·방명록 알림 스크롤·문의 딥링크가 상단바 높이를 가정한다. 상수 하나로(§3-1).
3. **`min-w-0`**(규칙 27) — 표지 두 칸 격자의 양쪽, 방문 정보 정의 목록. 긴 한 줄 소개·주소는 `break-keep [overflow-wrap:anywhere]`(규칙 30).
4. **어두운 테마** — 새 부품 전부를 그래파이트·네이비 배경에서 본다(문의 창의 입력 칸 · 소식 카드 날짜 · 전시 중 띠의 테두리).
5. **편집 화면 미리보기**(`compact`) — 표지가 절반 폭에서 두 칸이 되면 안 된다(컨테이너 폭 기준으로 가르거나 compact 면 한 칸).
6. **React #310**(규칙 Testing ⚠️) — `PortfolioPage` 는 로딩 분기 아래에 훅을 두면 죽는다. 컨텍스트 채우기 effect 를 early return 위에.
7. **핸들 주소**(규칙 49) — 숫자 주소 → `/@handle` 갈아끼우기(replace)와 작품 페이지의 push 가 꼬이지 않게: 갈아끼울 때 `location.search` 를 지키는 지금 코드 유지.
8. **앱(WebView)** — 내 사이트 모드에서 하단 탭이 없다 → 안드로이드 뒤로가기로 돌아간다(규칙 79 — 첫 화면이면 앱이 내려간다: 푸시로 홈페이지에 바로 들어온 경우 머리의 ArtLink 로고가 유일한 길). 에뮬레이터로 확인.
9. **소개 팝업·홈페이지 팝업**(규칙 51·73) — `introAllowedAt` 이 `isHomepagePath` 를 쓰게 되면 숫자 갤러리 주소(`/galleries/:id`)에서도 소개 팝업이 안 뜨게 된다. 의도한 변화다(규칙 73 의 취지) — 테스트 `guestIntro.test.ts`·e2e `73` 갱신.
10. **비회원 통계**(규칙 64) — 경로는 그대로라 영향 없음. 새 탭 값 `news` 의 이름표만 `guestPageKind` 에.
11. **`GalleryDetailPage` 의 `motion.div`** 가 페이지 전체를 감싼다 — sticky 머리와 transform 조상이 만나면 sticky 가 깨진다(지금은 탭 막대가 그 안에 있다). 표지를 떼어 낼 때 확인.
12. **개발 서버 겹침·stash 금지**(CLAUDE.md Commands · 규칙 77) — 고쳤는데 안 바뀌면 포트부터.
