### 4-2. 공모 한 건 화면 (WS)
- **WS-01 [P1·E2E]** 처음 탭 = 단계 기본 — 모집 중 지원자 · 전시 준비/전시 중 출품 자료 · 종료~정산 중 정산 · 정산 완료 요약 · 공모만 진행 지원자
- **WS-02 [P1·E2E]** `view=` — applicants/submissions/settlement/notices/summary 각각 그 탭 · 모르는 값 → 기본 탭 · **잠긴 탭**(`view=settlement`, 전시 종료 전) → 선택되지 않고 기본 탭(빈 화면 금지) · 정산 완료 전 `view=summary` → 기본 탭
- **WS-03 [P1·E2E]** 탭을 옮겨도 입력이 남는다 — 정산 판매가(미저장) → 공지 → 정산: 값 그대로 · 확인창 없음 · 지원자 거르기·선택도 유지
- **WS-04 [P0·E2E]** 권한 — 다른 갤러리 계정으로 남의 공모 `ex=` → '이 공모를 열 수 없어요' + [공고 보기], 운영 API(지원자·출품 자료·정산)는 403 이고 **응답에 남의 지원자 정보가 실리지 않는다** · 작가 계정으로 `tab=my-exhibitions&ex=` → 깨지지 않고 제 화면(프로필)으로 · 비로그인 → 로그인 화면 · 위임이 풀린 갤러리 → 열 수 없음 · 작가가 남의 전시 `tab=applications&ex=` → 내 지원이 없다는 안내(남의 정산·출품 자료 API 403)
- **WS-05 [P1·E2E]** 옛 운영 주소 `/exhibitions/:id/operation/new` — 갤러리 → 마이페이지 그 공모(`view` 유지) · 작가 → 그 전시 화면 · 관리자 → 단독 화면([← 운영 조회] 또는 [← 주최 공모]) · 일반(VISITOR) → 깨지지 않음 · `&panel=applicants` → 지원자 탭(기존: 35·63·33)
- **WS-06 [P2·E2E]** 없는 번호 `ex=999999` · 문자 `ex=abc` · 지워진 공모 → 열 수 없음/목록, `pageerror` 0
- **WS-07 [P1·E2E]** [⋯] 더 보기 — 단계별 항목(공고 보기 · '○○' 되돌리기 · 전시 종료 · 전시 확정 · 공모 삭제) · 막힌 되돌리기는 잠기고 이유 · 주 버튼과 같은 항목은 메뉴에 없다 · Esc·바깥 누르기 · 휴대폰에서 화면 안
- **WS-08 [P1·E2E]** 승인 대기·반려 공모의 화면 — 탭·할 일 버튼 없이 상태만(반려 사유) · 깨지지 않음
- **WS-09 [P2·E2E]** 공모 A 화면에서 벨의 공모 B 알림 → B 로 바뀜(제목·탭·숫자) · A 에서 열어 둔 창·선택이 남지 않는다
- **WS-10 [P1·E2E]** 주 버튼 자리 — 1024px 이상은 할 일 줄(`[data-task-bar]`)에만, 미만은 하단 줄(`[data-workspace-bar]`)에만 · 창 크기를 바꾸면 한쪽만 · 일괄 선택 중에는 하단 줄이 일괄 줄로
- **WS-11 [P1·E2E]** 삭제 — 수락 작가 없는 공모: [⋯] 공모 삭제 → '삭제' 입력 창 → 삭제 → 목록 · 수락 작가 있는 공모: 삭제 요청 창 → 대기 표시 → 메뉴에서 사라짐(기존: 66 F) · 아트링크 주최·관리자 화면에는 항목 없음
- **WS-12 [P2·E2E]** 머리 — 조회수는 올린 갤러리·관리자에게만 · 주최 배지 · [공고 보기]
- **WS-13 [P2·E2E]** 공지 탭 — 등록·수정·삭제 → 탭 수 · 작가 화면 반영 · 빈 제목/본문 검증 · 정산 완료 뒤 잠금 여부 기록

### 4-3. 지원 (APL)
- **APL-01 [P1·E2E]** 정상 — 상세 [지원하기] → 지원서 → [지원하기] → 확인 창('지원서를 보낼까요?' — 약력 · 경력 · 작품 사진 N장 · 포트폴리오 파일 · 추가 질문) → 약관 체크 → [지원하기] → 상세 '지원 완료' → [내 전시] 심사 중 줄 → 갤러리 알림 1(기존: 17 · 60 D)
- **APL-02 [P1·E2E]** 약관 — 체크 없이 [지원하기] → 창 그대로 + '약관에 동의해야 지원할 수 있어요.' · [약관 보기] 펼침/접힘(긴 약관이 창 안에서 스크롤) · [취소] → 폼 값 그대로
- **APL-03 [P1·E2E]** 빈 필수 — 약력 · 작품 사진 0 · 필수 추가 질문 → 확인 창이 열리지 않고 '아직 채울 것: …' + 그 칸으로
- **APL-04 [P0·API+E2E]** 이중 제출 — 동시 2요청 → 지원 1건(다른 하나는 400) · 갤러리 알림 1 · 화면은 성공 한 번
- **APL-05 [P1·E2E]** 실패 — `POST apply` 500/끊김 → 창·폼 유지 + 오류 토스트 → 다시 누르면 성공
- **APL-06 [P1·API]** 동의 기록 — 지원에 약관 판본(`ARTIST_APPLY_TERMS_VERSION`)이 남는다(창 안으로 옮긴 뒤에도) · `terms-consistency.test.ts` 통과
- **APL-07 [P2·E2E]** 추가 질문(글자 수 제한 텍스트 · 단일/다중 선택 · 파일) 공모 — 확인 창 '추가 질문' 줄 · 파일 업로드 뒤 제출
- **APL-08 [P2·E2E]** 사진 10장 · 약력 2,000자 → 확인 창이 390px 에서 넘치지 않는다(썸네일 줄 · 창 안 스크롤 · [지원하기] 가 화면 안)
- **APL-09 [P2·E2E]** [홈페이지 내용으로 다시 채우기] — 고친 값이 홈페이지 값으로 · 빈 홈페이지면 버튼 없음 · 위 회색 안내 상자 없음
- **APL-10 [P1·E2E]** 지원할 수 없는 공모의 지원서 주소 — 마감 지남 · 수동 마감 · 시작 전 · 이미 지원 → 상세로 돌려보냄 · 정원이 찼어도 지원은 받는다(규칙 57)
- **APL-11 [P2·E2E]** 쓰다 떠나기 → 확인 · 지원 성공 뒤에는 묻지 않는다
- **APL-12 [P2·E2E]** 비회원 [로그인하고 지원하기] → 로그인 → 그 공모로 돌아옴 → 지원

### 4-4. 지원자 심사 (REV)
- **REV-01 [P1·E2E]** 휴대폰 창 — 줄 → `dialog '<이름> 지원서'` · 머리의 이전/다음 · '검토 대기 i / n' · 아래 정원 한 줄 + [거절][수락하기] → 확인창 → 다음 검토 대기 → 마지막이면 닫힘(기존: 86 C)
- **REV-02 [P1·E2E]** PC 두 칸(≥1180px) — 줄을 누르면 오른쪽에 지원서 + 결정 줄 · 처음엔 검토 대기 첫 사람 · 결정 뒤 다음으로 · 1024~1179px 은 창
- **REV-03 [P0·E2E]** 정원 — 정원 2·수락 2 에서 수락 → 400 문구 토스트 · 줄 그대로 · [모집 인원 변경] 3 → 수락 성공 · 수락 수보다 작게는 400 · 0명/00명 표기(기존: 66 G 일부)
- **REV-04 [P0·API]** 동시 수락 — 정원 1 에 서로 다른 2명을 동시에 → 성공 1 · 실패 1 · 수락 알림 1 · 단톡 합류 1
- **REV-05 [P1·E2E]** 일괄 — 검토 대기 3 선택 → 일괄 줄(`[data-bulk-bar]`) → 확인창의 수 = 선택 수 → 토스트 · 정원에 걸리면 'k건 처리, m건 실패 — <이유>' · 끝나면 선택 해제(기존: 60 A)
- **REV-06 [P1·E2E]** 일괄 선택은 검토 대기 줄에만 · [전체 선택] 은 지금 거르기 안의 검토 대기만 · 골라 둔 사람을 한 줄 결정하면 선택 수에서 빠진다
- **REV-07 [P0·E2E] ⚠️가설 S6** — REL-06 의 첫 줄: 오류 뒤 B 의 줄이 '수락됨'으로 바뀌는가 · 창이 열려 있었다면 결정 줄이 사라지는가
- **REV-08 [P1·E2E]** 번복 — 거절한 지원은 수락으로만 바꿀 수 있다(서버) → 화면에 그 길이 있는지 · 수락 → 거절은 불가(개발자 플래그 ON 이면 가능 — VAR-07)
- **REV-09 [P1·E2E]** 전시 종료 뒤 잠금(기존: 66 H) + 관리자는 바꿀 수 있다(서버) → 관리자 화면의 버튼 유무 기록
- **REV-10 [P2·E2E]** 지원자 0명 — 빈 안내 + 도구 줄(모집 인원 변경 · 추가 질문 수정 · 초대 코드)
- **REV-11 [P2·E2E]** 도구 — 640px 미만 [관리 ▾](메뉴가 화면 안) · 이상은 글자 버튼 · 추가 질문 저장 뒤 다시 열면 바뀐 질문(기존: 71 B) · 지원서 전체 받기 진행률·누락 배너(기존: 28)
- **REV-12 [P2·E2E]** 거르기 탭 수 = 목록 · '검토 대기'에서 마지막을 결정하면 빈 안내 · 결정 뒤 수 갱신
- **REV-13 [P2·E2E]** 지원서 내용 — 사진 크게 보기 · 포트폴리오 파일 · 추가 질문 답 · '이 갤러리 n번째 지원' · '초대 코드로 참여'(빈 지원서)
- **REV-14 [P2·E2E]** 결정하는 동안 새 지원 도착 → 결정 뒤 목록에 새 줄 · '검토 대기 i / n' 갱신
- **REV-15 [P2·E2E]** 수락하면 작가에게 선정 알림 1 + 단톡방 합류(운영자가 첫 말을 하기 전엔 작가에게 안 보임 — 규칙 87) · 거절 알림 문구는 '지원 결과가 나왔어요.' 까지만

### 4-5. 모집 마감 · 단계 전환 · 되돌리기 (LIF)
- **LIF-01 [P1·E2E]** 검토 대기 0 — 확인창에 N명 줄·체크 없음 → '모집을 마감했어요.' → 띠 '전시 준비' → 탭이 출품 자료로 → 비회원 모집공고 목록에서 내려감(기존: 60 B)
- **LIF-02 [P0·E2E]** D2 체크 안 함(기본) — 대기 2 그대로 · 작가 화면 '심사 중' · 알림 없음 · 마감 뒤에도 수락/거절 가능
- **LIF-03 [P0·E2E]** D2 체크 — 대기 2 → 미선정 · 토스트 '모집을 마감하고 2명을 미선정으로 처리했어요.' · 작가별 `"<공모>" 지원 결과가 나왔어요.` 1건 · 수락자는 그대로 · 작가 줄 '이번 공모에서는 선정되지 않았어요' + [확인](기존: 86 B)
- **LIF-04 [P1·E2E]** 체크는 창을 열 때마다 꺼진 채로 시작(앞서 체크하고 취소한 뒤 다시 열어도)

- **LIF-06 [P0·API] ⚠️가설 S2** — `{recruitmentClosed:true, rejectPending:true}` 동시 2요청 → 작가별 결과 알림 **정확히 1건** · 두 응답의 `rejectedCount` 합 = 실제 바뀐 수
- **LIF-07 [P0·API] ⚠️가설 S2** — D2 처리와 같은 지원의 수동 거절/수락을 동시에(각 10회) → 최종 상태 하나 · 그 작가 알림은 그 결과 하나
- **LIF-08 [P1·E2E] ⚠️가설 S11** — 확인창(대기 1, 체크)을 연 채 다른 작가가 지원 → 마감 → 토스트의 수 = 실제 처리 수(2) · 두 작가 모두 알림
- **LIF-09 [P1·API]** `rejectPending` 은 전환 순간만 — 이미 마감된 공모에 다시 → 0(기존) · `rejectPending` 단독 → 무시 · `'true'`(문자열) → 무시 · 작가·남의 갤러리 → 403 · 전시 종료(`ended:true`)에 실어 보내도 대기를 건드리지 않는지 기록
- **LIF-10 [P1·E2E]** D2 뒤 [⋯] "'모집 마감' 되돌리기" → 모집공고에 다시 뜸 · 미선정은 그대로(수락으로만 바꿀 수 있다)
- **LIF-11 [P1·E2E]** 되돌리기 규칙 — 마감 되돌리기(확정·종료가 걸려 있으면 그것부터) · 확정 되돌리기(시작일이 지나 저절로 확정이면 잠김 + 이유 / 판매가 있으면 400) · 종료 되돌리기(판매·요청이 있으면 잠김 + '판매·정산을 시작해서…', 기존: 66 E) · 정산 완료 뒤 전부 잠김
- **LIF-12 [P1·E2E]** 확정을 건너뛴 종료 — 전시 준비 단계의 [⋯] 전시 종료 → 확인창(기간이 안 끝났으면 날짜 줄) → 작가에게 확정 알림이 1건 가는지 기록 → 정산 탭
- **LIF-13 [P1·E2E]** 확정 확인창 — '출품 자료를 아직 다 내지 않은 작가가 n명' 줄(있을 때만) · 시작일 줄 → '전시를 확정했어요. 작가에게 알림이 가요.'
- **LIF-14 [P2·E2E]** 공모만 진행 — 마감 확인창 문구 · 확정/종료 항목 없음 · API 로 `confirmed`/`ended` → 400
- **LIF-15 [P2·API]** 관리자는 순서와 무관하게 바꿀 수 있다 · 정산 완료 뒤 갤러리는 403, 관리자는 통과
- **LIF-16 [P2·E2E]** 전환 뒤 탭 이동 — 마감 → 출품 자료(공모만 진행은 지원자) · 확정 → 출품 자료 · 종료 → 정산

### 4-6. 출품 자료 (SUB)
- **SUB-01 [P1·E2E]** 작가 제출 — 출품작 2(사진·캡션) · 대표작 · 약력 · 작가노트 → [갤러리에 제출] → '✓ 갤러리에 제출했어요' → 갤러리 알림(기존: 60 C · 24)
- **SUB-02 [P0·API]** 알림 조건 — 임시저장만 ✗ · 출품작만 먼저 제출 ✗ · 다 채운 순간 ○(1) · 낸 뒤 고쳐 저장 ✗ · 비웠다 다시 채움 ○(안 읽은 줄이면 고쳐 쓰기) · 대신 입력으로 채움 ✗(기존 대부분)
- **SUB-03 [P0·API]** 한 줄 합치기 — 3명 차례: (1/3) → (2/3) → '모두 모였어요 (3/3)…' · 읽은 뒤엔 새 줄 · 동시 3명 → 1줄, 마지막 문구 3/3 · 운영자 여럿이면 각자 1줄(기존: 2명 동시)
- **SUB-04 [P1·API] ⚠️가설 S9** — 같은 작가의 첫 저장 동시 2요청 → 둘 다 200(500 없음) · 제출 행 1 · 알림 1줄 · 푸시 횟수 기록
- **SUB-05 [P1·API]** 대상 — 아트링크 주최 + 운영 갤러리 2 → 두 갤러리 주인 · 갤러리 없는 주최 → 관리자 전원 · 수락이 풀린 작가의 제출은 세지 않는다
- **SUB-06 [P1·E2E]** 갤러리 취합 — 탭 수 'c/r' · 줄 상태(시작 전 · 작성 중 · 제출 완료) · 펼치면 작품·대표작·약력·노트 · 임시저장 작품은 안 보임 · [새로고침]
- **SUB-07 [P1·E2E]** 안내 보내기 — 'n명에게 안내 보내기' → 창(받는 사람 = 안 낸 작가만) → 작가별 갠톡 + 알림 · 다 냈으면 버튼 없음
- **SUB-08 [P1·E2E]** 대신 입력 — 갤러리가 저장 → 작가 화면 '갤러리가 대신 입력한 자료예요' + 작가 알림 · 작가가 직접 고쳐 제출하면 안내가 사라짐 · 확정 뒤에도 갤러리는 대신 입력 가능
- **SUB-09 [P0·E2E] ⚠️가설 S5** — 작가가 편집 폼을 연 채 갤러리가 확정 → 작가 [갤러리에 제출] → 403 문구 · 쓴 내용은 화면에 남음 · 그 전시 알림을 누르거나 F5 → 잠긴 화면 + '갤러리가 전시를 확정해 출품 자료가 잠겼어요.'
- **SUB-10 [P1·E2E]** 잠금 — 확정 · 시작일 경과(자동) · 종료 각각의 안내 · 잠긴 뒤 미완성 작가 줄 문구('…다 차지 않은 채 전시가 확정되었어요. 갤러리에 문의해 주세요.')
- **SUB-11 [P1·E2E]** 작가 미저장 가드 — [← 내 전시] · 뒤로 · 다른 메뉴 → 확인 한 번(기존: 66 D2) · 전시 화면 안 탭 전환은 묻지 않고 값 유지
- **SUB-12 [P2·E2E]** 내려받기 — 휴대폰은 [내려받기 ▾] 메뉴(화면 안 · 하단 줄 위), PC 는 글자 버튼 넷 · 이미지 없는 출품작 안내 · 진행률(기존: 24·27·28)
- **SUB-13 [P2·E2E]** 판매가 입력된 작가는 출품 목록을 못 고친다(서버) — 종료를 되돌릴 수 없는 것과 한 쌍
- **SUB-14 [P2·E2E]** 출품작 20점 · 무공백 장문 제목 → 휴대폰 가로 밀림 0 · 하단 줄 '남은 것 N · <칸>' 한 줄 · 누르면 그 칸으로
- **SUB-15 [P2·E2E]** [출품작만 먼저 제출] 확인창 → 갤러리 줄 '작성 중' · 알림 없음 → 나중에 약력·노트를 채워 제출하면 알림
- **SUB-16 [P1·E2E]** 수락 되돌리기(개발자 플래그) → 그 작가 제출물 삭제 · 'c/r' 재계산 · '모두 모였어요' 판정이 바뀜

### 4-7. 전시 확정 · 전시 중 · 종료 (CNF)
- **CNF-01 [P0·API]** 확정 알림 — 수락 작가 전원 각 1(문구 · 링크 `/mypage?tab=applications&ex=<id>`) · 거절·대기 작가 ✗ · 수락 0명 ✗(기존)

- **SET-08 [P0·E2E]** 처리 ② 금액 그대로 — '○○ 님에게 다시 요청' → 그 작가 다시 · 알림 1 · 작가 줄 '정산 확인 요청이 왔어요'
- **SET-09 [P0·E2E]** 이의 2명 — '○○ 님 외 1명이 정산에 이의를 남겼어요' · 주 버튼이 둘 모두에게 · 작가 머리의 개별 [다시 요청] 은 그 한 명만
- **SET-10 [P0·E2E]** 옛 화면 409 — 작가가 정산 탭을 연 채 갤러리가 금액 수정·저장 → 작가 [정산 확인] → 409 문구 + 새 금액으로 다시 그림 → 다시 누르면 성공 · [이의 보내기] 가 409 면 **쓴 글이 창에 남는다**

- **SET-19 [P1·E2E] ⚠️가설 S7** — 판매가를 고치는 중(미저장)에 다시 알리기를 보내고, 그 사이 다른 작가가 확인 → 입력이 **남아 있다**(기대) · 사라지면 결함

## 부록 A. 환경 (반드시 지킬 것)

- 서버: 평소 **4000(복제본 `artlink_prod`) · 5173**. 데모 **4001(`artlink`) · 5183**(단계별 공모가 깔려 있다).

  1. 4000·5173 을 내린다(`kill -TERM -<pgid>` — `ss -ltnp` 로 pid → `ps -o pgid=`)

  3. `cd e2e && DATABASE_URL=…localhost:5432/artlink npx playwright test tests/<파일> --reporter=line`(주소에 Prisma 옵션 `?connection_limit` 금지)
  4. 끝나면 2 의 서버를 내리고 복제본 4000·5173 을 다시 띄운다 → 데모 DB 다시 깔기: `prisma migrate reset --force --skip-seed --skip-generate` → `tsx prisma/seed.ts` → `tsx scripts/seed-gallery-artists.ts` → `tsx scripts/seed-flow-stages.ts`

- **동시성**: `Promise.all` 로 서로 다른 `APIRequestContext` — 응답 코드가 아니라 **행 수·알림 수**로 판정. 한 번 통과로 끝내지 말고 10회.

- **두 탭**: 같은 `storageState` 로 컨텍스트 둘(또는 한 컨텍스트의 페이지 둘) — B 는 A 가 바꾸기 **전에** 화면을 다 띄워 둔다.

## 부록 C. 여정 끝에 돌릴 불변식 (데모·테스트 DB)

1. 수락 수 ≤ 정원: `Application` ACCEPTED 수 ≤ `Exhibition.capacity`
2. 안 읽은 합치기 알림은 사람·공모마다 한 줄: `Notification` 에서 `("userId","refKey")` 로 묶어 `read=false` 가 2 이상인 `submission:%` · `settle-all:%` 가 없다
3. 같은 사람에게 같은 문구의 `EXHIBITION_CONFIRMED` · D2 `APPLICATION_STATUS` 가 같은 초에 두 줄 없다
4. 정산 완료 공모: 수락 작가 전원 `SettlementApproval.status='APPROVED'` · `snapshot` = 지금 금액의 지문
5. `ArtworkSale.artworkIndex` < 그 작가 출품 목록 길이 · 판매의 작가는 수락 상태
6. 수락이 아닌 작가의 `ExhibitionSubmission`·`SettlementApproval` 이 남아 있지 않다(되돌리기 뒤)
7. 공모만 진행 공모에는 제출·판매·정산 행이 없다
