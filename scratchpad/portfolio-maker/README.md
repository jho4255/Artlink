# 포트폴리오 만들기 화면 하니스 (2026-10-03)

마이페이지 [포트폴리오] 탭(`frontend/src/components/portfolio-maker/`)이 **어느 엔진·어느 화면에서도 첫 화면에 내 PDF 가 보이고,
버튼이 눌리고, 꾸미는 동안 고친 쪽이 가려지지 않는지** 잰다. E2E(`e2e/tests/64-portfolio-maker.spec.ts`)는 크롬 한 엔진·한 화면으로
**로직**(눌러서 무슨 일이 나는가 · 무엇이 서버에 갔는가)을 보고, 여기는 **기하**와 **사파리 엔진**을 본다.

```bash
bash scratchpad/hero/setup-webkit.sh        # 최초 1회 — WebKit 을 sudo 없이 띄울 준비(~/.cache/wk-deps)
# 프론트(5173)와 백엔드(4000)가 **로컬 데모 DB(artlink)** 로 떠 있어야 한다. 실서버 복제본(artlink_prod)이면 스스로 멈춘다.
cd e2e && PLAYWRIGHT_SKIP_VALIDATE_HOST_REQUIREMENTS=1 node ../scratchpad/portfolio-maker/walk.js
#   ENGINE=webkit|chromium  한쪽만 · SCREEN="iPhone SE"  한 화면만 · SHOTS=1  스크린샷(out/) · VERBOSE=1  통과한 줄도
#   BASE=http://localhost:5183 API=http://localhost:4001/api  다른 포트로 띄웠을 때
#   DEMO_DATABASE_URL=…localhost:5432/artlink  backend/.env 가 복제본(artlink_prod)을 가리킬 때 — 계정을 심을 데모 DB
```

- 2 엔진 × 8 화면(PC 1280·1440·**1024**, 아이패드 미니, 아이폰 13·SE, 갤럭시 360, 픽셀 7) × 43~50항목 = **724 확인**(2026-10-03 사용자 검토 반영 뒤). 하나라도 어기면 종료 코드 1.
- 사용자 검토 뒤 화면(2026-10-03): PC 는 편집 패널이 **연 채로** 시작, 휴대폰은 아래 바가 **두 줄**(편집 탭 줄 + 버튼 줄, 113px), 용지는 맨 위.
  그래서 ① 에 '용지 세 칸이 눌린다'·'편집 패널/탭 줄'·'맨 위에서도 패널이 아래 바 위에서 끝난다' 가 더해졌고, ② 의 바 높이는 휴대폰 116px 이하로 본다.
  아이폰 SE(568px)는 첫 화면에 표지가 13px 만 보인다 — 두 줄 바와 용지 줄의 대가로 받아들였다(기준 8px).
- 계정 둘 — ① 작품 0점: `backend/scripts/seed-nudge-demo.ts`(시작할 때 다시 심는다) ② 작품 12점: 하니스가 **가입 + 진짜 업로드**로 만든다
  (`maker.walk@demo.artlink.local`, 한 번 만들면 다시 쓴다. 9점만 작품 정보가 있어 머리에 '작품 정보 채우기' 줄이 뜬다 = 첫 화면이 가장 길어지는 경우).
  진짜로 올려야 800px 썸네일이 생겨 ⑦(원본을 받지 않는다)을 잴 수 있다 — 시드 계정의 사진(`/demo-art/…`)에는 썸네일이 없다.
  ⚠️ **데모 DB 에 계정을 쓴다.** 주소는 `DEMO_DATABASE_URL` > `DATABASE_URL` > `backend/.env` 순으로 읽고 이름에 `prod` 가 있으면 거절한다.
  방금 심은 계정으로 로그인이 안 되면(= 백엔드가 다른 DB 로 떠 있다) 가입하기 전에 멈춘다 — 복제본에 가짜 계정을 만들지 않는다.
- 디자인 저장(`PUT /portfolio/design`)은 가로챈다 — 하니스는 DB 의 디자인을 바꾸지 않는다(시작할 때 처음 모양으로 되돌려 놓는다).

이 하니스가 실제로 잡은 것(전부 스크린샷으로는 "괜찮아 보이던" 것):
- (검토 뒤) **PC 에서 패널을 연 채로 시작하자 들어오자마자 표지로 스크롤돼 맨 위의 용지가 가려졌다** → 탭을 **누를 때만** 데려간다(`scrollReq`).
- (검토 뒤) **페이지 맨 위에서 패널 아래 ~300px 이 아래 바 뒤에 깔려** 그 안의 항목에 손이 닿지 않았다 → 패널 높이를 보이는 띠에 맞춘다(`CustomizePanel` 의 `fit`).
- **아이폰 SE(320×568)에서 첫 화면에 표지가 2px 만 보였다** — 머리의 할 일 줄(분홍 판, 좁은 화면에서 두 줄)·두 줄 설명·여백이 쌓여서다.
  → 할 일은 판 없는 한 줄(`TaskLine compact`)로 상태 옆에, 설명은 좁은 화면에서 한 문장, 디자인 줄·미리보기의 위 여백을 줄였다(표지 y441 → 355~375).
- **1024px 폭 PC 에서 [이름·연락처] 를 열면 패널의 탭·닫기가 상단바 뒤로 숨었다**(패널 y=−48). 패널은 미리보기 칸이 끝나는 곳에서 같이 밀려 올라가는데,
  그 묶음은 마지막 장으로 데려가고, 좁은 칸의 마지막 장(385px)이 패널(584px)보다 낮았다 → 마지막 칸을 패널 높이만큼 받쳐 둔다(`BookPreview tailRoom`).
- 꾸미기 탭 **'표지' 의 누르는 폭이 24px**(글자 폭 그대로), 디자인 [접기] 24px, 강조색 '글자색' 칸의 글자 10px → 탭 `min-w-[40px]`+여백, '가' 한 글자.
- (E2E 가 먼저 잡은 것) 휴대폰에서 꾸미기를 열면 표지 아랫부분이 시트에 12px 가렸다 — 쪽 위 이름 줄이 단추 있는 쪽만 40px 이었다(`PAGE_LABEL_H`).

⚠️ 눌림 판정은 `elementFromPoint` 다 — **화면 안에 있는 요소만** 잰다. 창 안에서 스크롤해야 나오는 것(저장 창의 [인쇄 창 열기])은 `scrollIntoViewIfNeeded` 뒤에.
⚠️ 글자 크기는 `[data-scaled-page]`(줄여 그린 지면) **밖**만 센다 — 지면 안의 글자는 PDF 의 글자다.
⚠️ 묶음을 바꾼 뒤에는 스크롤이 멎을 때까지 기다린다(`settle`) — `scrollIntoView({behavior:'smooth'})` 가 엔진마다 걸리는 시간이 다르다.

## 그 밖의 스크립트
- `shot.js <full|partial|empty> <pc|pcl|pixel|iphone|se> [click=…|tab=…|wait=…|full]` — 화면 찍어 보기(개발 중 눈으로).
- `export.js [works=10|30] [screen=pc|pixel|iphone] [throttle=4] [engine=chromium|webkit] [acc=이메일]` — **실제로 내려받아 본다**(시간·용량·쪽수).
  2026-10-03 실측: 12점 11쪽 — 크롬 PC 5.8초 5.7MB · WebKit(아이폰 13 화면) 8.7초 6.0MB. 30점 12쪽 — 크롬 PC 6.9초, CPU 4배 느리게 19.4초(예전 이미지형 경로 43.6초).
- `shrink.js [budgetMB…]` — 용량 맞추기: 예산을 일부러 작게 주고 줄이는 단계와 결과 해상도를 본다(2MB → 182dpi, 0.5MB → 134dpi).

셋 다 기본 주소가 5183/4001 이다(예전 조사 때의 데모 서버). 5173/4000 으로 띄웠으면 `BASE=… API=…` 를 준다.
