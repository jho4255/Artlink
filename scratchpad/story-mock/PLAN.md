# ArtStory 홈 공개 — 계획 (2026-11-14, 초안 3)

목업: https://claude.ai/artifact/M5JRtdgsX3mnqspwacD6o1 (비공개 — 본인만 열림)
상태: **계획만**. 코드는 아직 한 줄도 안 고쳤다. 구현은 사용자가 시작하라고 할 때.

## 0. 초안 2에서 고친 것 (사용자 지적 넷 + 검수)

사용자 지적
1. 휴대폰 올리기가 휑하고 여백이 안 맞는다 → 빈 편집 화면을 없앴다. [+ 올리기]는 **고르는 창**(사진 고르기 / 내 작품에서 고르기 / 글만 쓰기)만 띄우고, 고르면 **화면 전체가 곧 미리보기인 편집 화면**으로 들어간다(보기 화면과 같은 모양).
2. PC 카드 줄의 아래 스크롤바가 "여기가 끝"처럼 보인다 → 스크롤바를 없애고 **양옆 화살표로 네 장씩 넘긴다**. 오른쪽 끝 카드는 잘려 보여 더 있다는 걸 알린다. 보기 창에서도 **앞·뒤 소식이 양옆에 작게** 보여 넘기며 보는 화면임이 드러난다.
3. 댓글·좋아요·공유 → PC 보기 창에도 다 넣었다. 댓글은 **보기 창 오른쪽에 붙는 칸**으로 열리고(열려 있는 동안 넘김 멈춤), 공유는 그 소식 주소를 복사한다(휴대폰은 기기의 공유 창).
4. "누구나 올리고 모두가 봐요" 같은 설명 문구 → 전부 뺐다(아래 원칙).

검수에서 더 찾아 고친 것
- 설명 문구가 그 한 줄만이 아니었다. 뺀 것: 올리기 화면의 "올리면 홈 맨 앞에 이 모양으로…·사진은 자르지 않아요" · 공개 범위 옆의 "홈에 보여요/홈에는 안 보여요" · 작품 고르는 창의 "누른 순서대로 실려요·다시 올리지 않아도 돼요" · 다 본 화면의 "오늘 작업실에서 있었던 일을…" · 올린 뒤 화면의 "홈 맨 앞에 보여요. 내 홈페이지에도 남아요" · 로그인 안내의 "로그인하면 이 소식으로 돌아와요" · 올리기 칸의 "사진 한 장이면 돼요" · PC 보기 창의 "방향키로 넘기고…".
- **올린 뒤 확인 화면을 없앴다.** 올리면 바로 홈으로 돌아가고 내 카드가 줄 맨 앞에 있다(짧은 알림 "소식을 올렸어요"). 한 단계가 줄었다.
- 공개 범위 이름을 지금 ArtStory가 쓰는 말로 맞췄다: **전체 공개 / 이웃 공개**.
- PC의 [멈춤] 글자 단추 → 멈춤·재생 아이콘.
- 더 보기 메뉴에 남의 소식용·내 소식용이 한 창에 섞여 있었다 → 따로.
- **좋아요 알림을 1차로 올렸다.** 지금 소식 좋아요는 알림이 없다. 올린 사람이 반응을 못 느끼면 다시 안 올린다 — 이 개편의 목적(다시 오게 하기)에 가장 싸게 닿는 길이다. 글 좋아요와 같은 방식(소식마다 한 줄로 합침).
- 일반 회원은 홈페이지가 없다 → 보기 화면의 [홈페이지]는 작가·갤러리일 때만.
- 보기 화면을 닫으면 **홈 줄이 마지막에 본 카드 자리로** 와 있어야 한다(초안 2에 없던 규칙).

## 1. 원칙

- **화면은 스스로 설명하지 않는다.** 제목·버튼·상태만 둔다. 문장은 사용자가 무언가를 눌렀는데 막혔을 때만(로그인 필요, 올리지 못함). 공모 등록 폼·지원서에서 안내 글자를 뺀 것과 같은 기준.
- 사진은 어디서도 자르지 않는다. 남는 자리는 같은 사진을 흐리게.
- 휴대폰과 PC가 같은 순서로 같은 일을 한다(줄 → 넘기며 보기 → 좋아요·댓글·공유·이웃).

## 2. 왜

- 지금 ArtStory(`/feed`)는 내가 이웃한 사람 + 나의 소식만, 로그인해야 보인다.
- 실서버 복제본(9월 말): **소식 0건 · 이웃 관계 7건 · 하이라이트 0건**.
- 방향(사용자 결정): 블라인드 스토리처럼 이웃이 아니어도 모두의 소식을 홈에서. 작업·전시가 중심이되 일상도 괜찮다.
- '이웃'은 남는다. 뜻이 "보려면 필요한 것"에서 "놓치지 않으려는 것"으로 바뀐다(전체 보기의 [이웃] 탭).

## 3. 보기

### 3-1. 홈의 카드 줄
- 자리: 배너 아래, ArtWorks 위.
- 머리: `ArtStory` · [전체 보기] · [+ 올리기]. 그 밖의 글자 없음.
- 카드 세로 3:5 — 휴대폰 148×246(두 장 반), PC 184×306. 왼쪽 위에 올린 사람, 여러 장이면 `1/3`. 글만 있는 소식은 바탕색 위에 글.
- 휴대폰: 손가락으로 민다. **PC: 스크롤바 없이 양옆 화살표로 네 장씩**, 끝 카드는 잘려 보인다. 트랙패드 가로 밀기도 된다.
- 최신 12장. 한 사람당 가장 새 소식 1장. 4장보다 적으면 맨 앞에 올리기 칸.

### 3-2. 보기 화면
- 위: 진행 막대(사진 한 장 = 한 칸) · 올린 사람 · 역할·시각 · [이웃 추가] · (PC) 멈춤/재생 · 닫기.
- 아래: 글 · **좋아요 · 댓글 · 공유** · [홈페이지](작가·갤러리만) · 더 보기.
- 넘김: 사진 5초, 글만 6.5초, 사진이 다 뜬 뒤부터 센다. 마지막 장이 끝나면 다음 사람으로. 왼쪽 1/3 = 이전, 오른쪽 = 다음, 누르고 있으면 멈춤.
- 휴대폰: 옆으로 밀면 다음/이전 소식, 아래로 밀면 닫기. 댓글은 아래에서 올라오는 창.
- PC: 가운데 세로 창 + **양옆에 앞·뒤 소식이 작게**(누르면 그리로) + 화살표 · 방향키 · Space · Esc. 댓글은 **오른쪽에 붙는 칸**.
- 멈추는 때: 댓글·더 보기가 열려 있을 때, 탭이 가려졌을 때, 기기의 '움직임 줄이기'가 켜져 있을 때.
- 끝: "새 소식을 다 봤어요" + [소식 올리기] [홈으로].
- 닫으면 홈 줄이 마지막에 본 카드 자리에 있다.
- 공유: 주소 `/feed?story=<id>`. 휴대폰은 기기 공유 창(앱은 `shareLinkNative`), PC는 주소 복사. 카카오톡에 붙이면 그 소식 사진이 미리보기로 뜬다(`seoMeta`).
- 비회원: 보는 건 된다. 좋아요·댓글·이웃을 누르면 로그인 창 → 로그인 뒤 그 소식으로 돌아온다.
- `HighlightViewer`를 일반화해 하이라이트와 같이 쓴다. `role="dialog" aria-modal` + Esc.

### 3-3. 전체 보기 = `/feed`
- 탭 [전체 · 이웃 · 내 소식]. 전체는 비회원도 본다.
- 세로 카드 격자(휴대폰 2열, PC 5열), 내리면 더 받는다. 누르면 같은 보기 화면.

## 4. 올리기

1. [+ 올리기] → 고르는 창: **사진 고르기 / 내 작품에서 고르기 / 글만 쓰기**.
2. 고르면 화면 전체가 편집 화면(어두운 바탕, 보기 화면과 같은 모양).
   - 사진: 가운데에 사진, 아래에 사진 줄(보기·빼기·더 넣기, 10장) + 글 칸.
   - 글만: 바탕색 위에 바로 쓴다. 아래에 바탕색 여섯.
   - 맨 아래: [전체 공개 | 이웃 공개] · 글자 수. 오른쪽 위: **[올리기]**.
3. 올리면 홈으로 돌아가고 내 카드가 줄 맨 앞. 알림 한 줄.

챙길 것
- 전용 화면(`/story/new`, Layout 밖). PC는 가운데 세로 창으로 같은 편집 화면.
- 자판이 올라오면 글 칸과 [올리기]가 자판 위에 보인다(`useVisualViewport`).
- 사진은 고르는 대로 올리기 시작, 칸마다 진행·실패·다시 시도. 다 올라가기 전엔 [올리기]가 잠긴다.
- 쓰던 것은 이 기기에 남긴다. [올리기]는 한 번만 먹는다.
- 고친 채로 닫으면 묻는다(버리기 / 계속 쓰기).
- 들어오는 길: 홈 줄 · 올리기 칸 · 보기 화면 끝 · `/feed` · ArtLook 저장 뒤 [ArtStory에 올리기].
- [내 작품에서]: 홈페이지 작품을 다시 올리지 않고 싣는다. 작품을 지워도 소식 사진이 안 깨지게 "소식이 쓰는 파일은 지우지 않는다" 규칙이 함께 필요.

## 5. 순서

- 최신순. 홈 줄은 한 사람당 1장. 같은 사람이 연달아 안 나오게.
- 이 기기에서 본 소식은 뒤로(기기에만 기억).
- 기간으로 자르지 않는다 — 최신 12장이 곧 창이다.

## 6. 모두에게 보이는 만큼 필요한 것 (1차에 같이)

- **신고**: 한 사람이 한 소식에 한 번. 서로 다른 3명이면 홈·전체 보기에서 자동으로 내리고 관리자 확인 대기.
- **운영이 내리기/되살리기**: 지우지 않고 가린다. 올린 사람에게 알림.
- **이 사람 소식 그만 보기**: 내 화면에서만 빠진다.
- 하루 10개까지.
- 내 소식: [이웃 공개로 바꾸기] · [삭제].
- 익명은 두지 않는다.

## 7. 서버·DB

| 무엇 | 내용 |
|---|---|
| `GET /api/stories/public` | 로그인 없이. 전체 공개 + 안 가려진 것 + 탈퇴 아님 + 내가 그만 보기 한 사람 제외. `?limit=`·`?cursor=`·`?rail=1` |
| `Story.visibility` 기본값 | `NEIGHBORS` → `PUBLIC`(서버·화면). 이미 있는 소식은 그대로 — 배포 전 실서버 소식 수를 다시 센다 |
| `Story.bg` | 글만 소식 바탕색(여섯 값만) |
| `Story.hiddenAt` | 가린 시각 |
| `StoryReport` · `StoryMute` | 각각 (소식, 신고자) · (나, 그만 볼 사람) unique |
| 좋아요 알림 `STORY_LIKE` | 소식마다 한 줄로 합침 · 내 소식에 내가 누른 건 제외 · 푸시 제목 추가 |
| 가려진 소식 | 주인·관리자 말고 404. 댓글·좋아요 라우트도 같은 판정 |
| 공유 미리보기 | `/feed?story=` 에 og:image·제목 |

마이그레이션 1개. Render 환경 변수 변경 없음.

## 9. 나눠서 하기

- **1차**: 공개 목록 · 홈 줄(휴대폰·PC) · 보기 화면(좋아요·댓글·공유·이웃) · 올리기(사진·글만) · 기본 전체 공개 · 좋아요 알림 · 신고·내리기·그만 보기 · 전체 보기 · 테스트.
- **2차**: [내 작품에서] · 이웃이 올리면 알림 · "N명이 봤어요" · 동영상 · 순서 다듬기 · Admin [통계].

## 10. 확인

- 백엔드: 공개 범위 · 사람당 1장 · 신고 3건 자동 내림 · 동시 신고·올리기 · 그만 보기 · 좋아요 알림 한 줄.
- 프론트: 넘김·순서·본 소식 기억(순수 함수) · 소스 가드(자르지 않기, dialog, **설명 문구 없음**).
- E2E: 올린다 → 다른 사람·비회원 홈에 뜬다 → 누르면 넘어간다 → 좋아요에서 로그인 → 돌아온다 → 댓글 → 공유 → 신고.
- 하니스: 크롬 + 사파리 엔진 × 휴대폰·PC(PC 화살표로 끝까지 넘어가는지 · 보기 창 버튼이 화면 안에 있는지 · 자판 위 [올리기]).
- 실기기: 안드로이드 에뮬레이터 · 아이폰 사파리.
- 복제본에 가상 데모 계정으로 소식을 채워 사용자가 직접 본다.
